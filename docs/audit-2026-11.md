# Audit de code - novembre 2026

**Date** 2026-11-11 · **Base** `Develop` au commit `3320a4f` (version 0.0.2) · **Statut** corrections
appliquées

Audit de la qualité, de la maintenabilité, de la robustesse et de la performance du cœur Rust
(21 000 lignes) et de l'interface Vue (stores, IPC, composants). Chaque défaut corrigé a un test ;
onze de ces tests, rejoués sur le code d'origine, y échouent (§ 2). Chaque gain de performance est
mesuré.

## 1. Verdict

Le code d'origine est sain : format, lint, typage, Clippy et les 586 tests passaient déjà. L'audit
n'a pas trouvé de défaut d'architecture. Il a trouvé **douze défauts de robustesse** dans des cas
limites (annulation, liens, secrets, erreurs réseau, double envoi) et **trois coûts évitables**.
Tous sont corrigés ; cinq points restent ouverts (§ 5) parce qu'ils demandent une décision.

## 3. Défauts corrigés

### Cœur Rust

| N°  | Défaut constaté sur le code d'origine                                                                                                                                                            | Correction                                                                                                         | Preuve                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| R1  | **Annuler un run laissait partir des requêtes.** `notify_waiters` ne réveille que les envois déjà en attente : une requête en train de lire son fichier partait quand même, écritures comprises. | `http::Cancel` mémorise l'annulation ; `send` la voit même demandée avant lui.                                     | `annuler_un_run_n_envoie_plus_aucune_requete` : avant, 2 requêtes envoyées dès l'essai 0 ; après, 0 sur 240 essais. |
| R2  | **Un lien symbolique vers un dossier parent bloquait la lecture de l'arborescence** (deux liens doublent l'arbre à chaque niveau).                                                               | Les chemins réels des dossiers parents sont suivis ; un lien qui y ramène est ignoré, un lien externe reste suivi. | `liens_en_boucle_ignores_liens_externes_suivis` : avant, pas de fin en 45 s ; après, quelques millisecondes.        |
| R3  | **Un secret contenu dans un autre laissait lire la fin du plus long** (`abc` et `abcdef-123` donnaient `••••def-123`).                                                                           | Masquage des valeurs les plus longues d'abord.                                                                     | `un_secret_contenu_dans_un_autre_ne_le_devoile_pas`.                                                                |
| R4  | Un en-tête au nom ou à la valeur invalides (`Content Type`, retour à la ligne) donnait « L'adresse de la requête est invalide ».                                                                 | En-têtes vérifiés avant l'envoi ; le message nomme l'en-tête.                                                      | `en_tete_invalide_nomme_dans_le_message`.                                                                           |
| R5  | Serveur arrêté, nom introuvable et **certificat ou TLS refusé** donnaient le même message, sans cause.                                                                                           | La cause première de l'erreur est ajoutée au message ; trop de redirections a son message.                         | `echec_de_connexion_donne_sa_cause`, `cause_premiere_d_une_chaine_d_erreurs`.                                       |
| R6  | Chaque run restait en mémoire jusqu'à la fermeture d'Arnod.                                                                                                                                      | 20 runs terminés gardés (`MAX_FINISHED_RUNS`) ; un run en cours n'est jamais oublié.                               | `les_runs_termines_anciens_sont_oublies` ; à l'origine, aucune suppression dans le code.                            |
| R7  | « Relancer les échecs » échouait après un redémarrage (« Ce run n'existe plus »).                                                                                                                | Repli sur le dernier run du projet, gardé sur disque.                                                              | `le_dernier_run_se_relance_apres_un_redemarrage` (non rejoué sur l'origine).                                        |
| R8  | Une requête nommée « Con! » ou « nul ? » créait `con.yml` ou `nul.yml`, noms réservés par Windows.                                                                                               | Nom de fichier préfixé (`_con.yml`).                                                                               | `nom_de_fichier_jamais_reserve_par_windows`.                                                                        |
| R9  | Une réponse tronquée à 5 Mo au milieu d'un caractère accentué finissait par « � » et dépassait la limite.                                                                                        | Le caractère coupé est retiré.                                                                                     | `troncature_sans_caractere_coupe`.                                                                                  |

### Interface

## 4. Performance mesurée

Banc sur un projet de 500 requêtes en 20 dossiers, build optimisé, médianes.

| Opération                                                    | Avant   | Après            |
| ------------------------------------------------------------ | ------- | ---------------- |
| Sérialisations de brouillons par frappe, 4 requêtes ouvertes | 16      | 1                |
| Masquage des secrets d'une réponse de 5 Mo (secret absent)   | 7,39 ms | 0,32 ms          |
| Validation de `opencollection.yml` contre le schéma          | 0,19 ms | moins de 0,01 ms |
| Lecture de l'arborescence (500 requêtes)                     | 27,9 ms | 27,4 ms          |
| Envoi HTTP local, en série                                   | 0,22 ms | 0,22 ms          |

- La sérialisation des brouillons croissait avec le nombre d'onglets ouverts (enregistrement
  automatique, pastilles des onglets et de l'arbre) : elle est maintenant mémorisée par requête.
- Lecture de l'arborescence et envoi étaient déjà rapides : la protection contre les liens en
  boucle et la vérification des en-têtes n'ont pas de coût mesurable.

## 5. Points ouverts (non modifiés)

| N°  | Constat                                                                                                                 | Pourquoi une décision                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| O1  | Fermer une fenêtre détachée dont l'enregistrement échoue la rattache quand même : le brouillon est perdu (`App.vue`).   | Garder la fenêtre ouverte avec un message change la règle Z6.                                                 |
| O2  | Un client HTTP neuf par envoi : pas de réutilisation des connexions, donc une poignée de main TLS par requête d'un run. | Réutiliser les connexions change les durées mesurées ; gain non mesurable ici (pas de serveur HTTPS de test). |
| O3  | Le contrat lié est relu et analysé pour chaque requête d'un run de contrat.                                             | Un cache par run est à dessiner ; coût non mesuré sur un gros contrat.                                        |
| O4  | Les environnements ne lisent que `.yml`, l'arborescence lit `.yml` et `.yaml`.                                          | Choix de format.                                                                                              |
| O5  | Un envoi lit deux fois le coffre des secrets (contrôle de l'environnement protégé, puis envoi).                         | Coût faible sous Windows, à mesurer avec Secret Service sous Linux.                                           |

## 6. Limites de cet audit

- Vérifié sous Linux uniquement : ni build Windows, ni installeur NSIS, ni tests e2e (`tauri-driver`)
  n'ont été lancés. Aucune dépendance n'est ajoutée : la taille de l'installeur ne change pas.
- Les dépendances n'ont pas été auditées (`npm audit`, `cargo audit`).
- Lecture ciblée, pas ligne à ligne : `opencollection/request.rs`, `contract/generate.rs`,
  `layout/` et la plupart des composants Vue n'ont été relus que par sondage.
